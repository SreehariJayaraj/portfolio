Recently, I went through the interview process for an SDE 1 Frontend role at Headout. In this blog, I’ll break down the rounds, questions, and what they were actually evaluating.

If you're preparing for frontend roles (especially product companies), this should give you a clear idea of what to expect.


## About Me

I’m a frontend-leaning full-stack developer, currently working as a Founding Engineer at CredHive, where we build credit reporting and monitoring solutions for Indian companies and MSMEs.

My core strengths are React, TypeScript, and building highly interactive UI systems. I also work with backend stacks like NestJS and Python when needed.


## Interview Process Overview

The process had roughly **3–4 rounds**:

1. **Recruiter Call**
2. **Vanilla JS Machine Coding Round**
3. **React + TypeScript Machine Coding Round**
4. **Hiring Manager / Culture Fit**


## Recruiter Call

This was a typical recruiter screening round.

### Questions

- Current compensation  
- Location / willingness to relocate  
- Why are you leaving your current organization  

### What They Expect

- Clear communication  
- Basic alignment with the role  


## Round 2: Vanilla JS Machine Coding

This was an **elimination round**.

They were not just looking for working code. They wanted to understand **how you think as a frontend engineer**, especially around performance and structure.

### Problem

Build a UI with:

- API integration  
- Loading state  
- Error handling  
- Search / filtering  
- Basic optimizations  

### What They Evaluated

#### 1. Code Structure

- Separation of concerns  
- Reusability  
- Clean functions  

#### 2. State Handling

- Avoid unnecessary re-renders  
- Efficient updates  

#### 3. Edge Cases

- Empty state  
- API failures  
- Loading states  

#### 4. UX Thinking

- Debouncing search  
- Smooth interactions  
- Basic accessibility  


## Round 3: React + TypeScript Machine Coding

This was the most interesting round.

The problem was to **build a Toast system from scratch**.

### Requirements

- Toast stacking (multiple toasts at once)  
- Auto dismiss after a timeout  
- Manual close  
- Different positions (top-right, bottom-left, etc.)  
- Smooth enter and exit animations  

### What They Focused On

#### 1. Architecture

- How you design the toast system  
- Global state vs local state  
- Reusability  

#### 2. State Management

- Managing multiple toasts  
- Handling add/remove logic cleanly  

#### 3. Rendering Strategy

- Rendering at different positions  
- Using portals (bonus)  

#### 4. TypeScript

- Proper typing of toast data  
- Avoiding `any`  

#### 5. Performance

- Avoid unnecessary re-renders  
- Clean updates  

The discussion went quite deep into **why I chose a particular approach** and how I could improve it.

The entire round lasted around **1.5 hours**, including implementation and discussion.


## Round 4: Hiring Manager Round

This was more discussion-driven.

### Topics

- Past projects  
- Decision making  
- Ownership  
- Trade-offs  

Since I’m working as a founding engineer, most of the discussion was around:

- Scaling frontend systems  
- Handling complex state  
- Working in fast-moving environments  


## Result

I cleared all the interview rounds successfully.

However, I was informed that the role had already been filled by another candidate, so they couldn’t extend an offer.

Even though I didn’t convert this opportunity, the process gave me strong validation that I’m on the right track for frontend roles at product companies.

Overall, it was a great learning experience and a confidence boost.
